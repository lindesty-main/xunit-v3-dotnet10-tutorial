# 第 4 章 · 参数化测试

> 你将学会:
>
> - 理解"一行数据 = 一个测试用例"在计数、失败定位、过滤上的实际含义
> - 用 `[InlineData]` 时知道字面量的边界:哪些值能写、`decimal` 为什么不行、数组字面量的两种语义
> - 用 `[MemberData]` 把数据搬到方法/属性/字段里,三种行格式(`object?[]`、元组、`TheoryDataRow`)、async 数据源、带参数的数据源
> - 用 `[ClassData]` 把可复用的输入表做成类型,被多个测试类共用
> - 用 `TheoryData<T…>` 把参数类型错误停在编译期,并读懂分析器的报错
> - 用 `TheoryDataRow` 的 `TestDisplayName` / `Skip` / `Timeout` / `Traits` 让单行可读、可跳过、可过滤,并用 `--filter-display-name` 精确重跑一行

第 2 章的判定流程停在"这该写成 Theory"。本章从下一步开始:数据从哪里来,以及一行数据在 runner 眼里到底是什么。

本章的工程是 [`code/Ch04.Parameterized`](../code/Ch04.Parameterized),被测代码在 [`Production/`](../code/Ch04.Parameterized/Production/):`TrackingNumberParser`(运单号 = 2 位承运商代码 + 12 位数字)与 `ShippingEstimator`(区域首重价 + 每 500g 阶梯加收 + 加急固定附加费)。所有输出片段来自本机 .NET SDK 10.0.113 + xUnit.net v3 4.0.2 的真实运行;过长的绝对路径用 `...` 省略,其余逐字保留。

## 4.1 一行数据就是一个测试用例

[`InlineDataTests.cs`](../code/Ch04.Parameterized/InlineDataTests.cs) 里最小的一个 Theory:

```csharp
[Theory]
[InlineData("SF123456789012", "SF", "123456789012")]
[InlineData("YT000000000001", "YT", "000000000001")]
[InlineData(CarrierJdTrackingNumber, "JD", "999999999999")]
public void TryParse_ValidTrackingNumber_SplitsCarrierAndDigits(string input, string expectedCarrier, string expectedDigits)
{
    Assert.True(TrackingNumberParser.TryParse(input, out var parsed));

    Assert.Equal(expectedCarrier, parsed.Carrier);
    Assert.Equal(expectedDigits, parsed.Digits);
}
```

它不是一个"跑了三次的测试",而是三个测试。报告里出现的是三行,各自带自己的参数(这三行的显示名都能在 4.8 那条 `--report-xunit-xml` 生成的报告文件里找到;报告里引号被写成 `\&quot;`,下面按命令行里的形式还原,报告中的行序也不保证与数据顺序一致):

```text
Ch04.Parameterized.Tests.InlineDataTests.TryParse_ValidTrackingNumber_SplitsCarrierAndDigits(input: "SF123456789012", expectedCarrier: "SF", expectedDigits: "123456789012")
Ch04.Parameterized.Tests.InlineDataTests.TryParse_ValidTrackingNumber_SplitsCarrierAndDigits(input: "YT000000000001", expectedCarrier: "YT", expectedDigits: "000000000001")
Ch04.Parameterized.Tests.InlineDataTests.TryParse_ValidTrackingNumber_SplitsCarrierAndDigits(input: "JD999999999999", expectedCarrier: "JD", expectedDigits: "999999999999")
```

三条后果,后面每一节都建立在这上面:

- **计数按行**。本章工程只有 29 个测试方法,跑出来是 108 个测试:每个方法被数据行展开成若干行,一行算一个。
- **失败按行**。一行失败,其它行照跑;失败输出里带的是这一行的参数值(4.5、4.6 有真实输出)。
- **过滤按行**。`--filter-display-name` 可以只选中一行(4.8),`--filter-trait` 只选中带某个标签的行(4.6)。

还有一条:**元数据也能按行挂**。显示名、跳过原因、超时、标签都可以只作用于某一行(4.6)。这是 v3 数据行与 v2 最大的差别——数据不再只是参数,而是一条带属性的测试记录。

## 4.2 InlineData:字面量能表达什么

`[InlineData]` 的参数是 C# 特性参数,所以它只能写**编译期常量**。可用的写法:

| 想要的值 | 写法 |
| --- | --- |
| 字符串、字符、整数、浮点、布尔 | `"SF123456789012"`、`'0'`、`500`、`1_000`、`1.5`、`true` |
| 枚举成员 | `ShippingZone.Eu` |
| 常量与 `nameof` | `FirstWeight`、`FirstWeight + 1`、`2 * FirstWeight`、`nameof(ShippingZone.Eu)` |
| `typeof` | `typeof(ShippingZone)` |
| 数组创建表达式 | `new[] { 500, 1000 }`、`new int[0]`、`new byte[] { 1, 2 }` |
| `null` | 参数要声明成可空类型(`string? input`) |

[`InlineDataTests.cs`](../code/Ch04.Parameterized/InlineDataTests.cs) 里这张表把枚举、布尔、整数、常量表达式一次用全:

```csharp
[Theory]
[InlineData(FirstWeight, ShippingZone.Domestic, false, 12.00)]
[InlineData(FirstWeight + 1, ShippingZone.Domestic, false, 15.00)]
[InlineData(2 * FirstWeight, ShippingZone.Eu, false, 31.00)]
[InlineData(FirstWeight, ShippingZone.Eu, true, 39.50)]
[InlineData(1_000, ShippingZone.International, true, 81.00)]
public void Estimate_KnownCombination_ReturnsExpectedPrice(
    int weightGrams, ShippingZone zone, bool express, decimal expected)
    => Assert.Equal(expected, estimator.Estimate(weightGrams, zone, express));
```

三个必须知道的限制。

**一:`decimal` 字面量不能出现在特性里。** 把上面第一行写成 `12.00m`,编译直接停:

```text
error CS0182: An attribute argument must be a constant expression, typeof expression or array creation expression of an attribute parameter type
```

只能写 double 字面量 `12.00`,绑定参数时 xUnit 会把它转成 `decimal`。这个转换是宽容的,4.5 会看到宽容的代价。

**二:只有 `const`,没有 `static readonly`。** 同一个 CS0182:`private const int FirstWeight = 500;` 能用在特性里,`private static readonly int FirstWeight = 500;` 不能。

**三:数组字面量的语义取决于元素类型。** `InlineData` 的形参是 `params object?[]`,所以 `new object?[] { … }` 正好就是那个 `params` 数组本身:当它是特性里唯一的数据时,元素直接变成多个参数。想给 `int[]` 参数传"两个重量",写成 `[InlineData(new object?[] { 500, 1000 })]` 就掉进这个坑,运行时报的是 `The test method expected 1 parameter value, but 2 parameter values were provided.`

元素类型不是 `object?` 时没有这个歧义:`new[] { 500, 1000 }` 是 `int[]`,而 `int[]` 不能隐式转成 `object?[]`,所以整个数组是一个值,正常绑定到 `int[]` 参数——上面表格里"数组创建表达式"那一行,工程里就是 `EstimateBatch_MultiParcelOrder_SumsEveryParcel` 在用。

数组后面还跟着别的数据时(工程里带 `Skip` 保留的这一行),不会被摊平,挡住你的是类型:`object?[]` 不是 `int[]`,分析器在编译期就停([`InlineDataTests.cs`](../code/Ch04.Parameterized/InlineDataTests.cs)):

```csharp
[Theory(Skip = "演示:object?[] 与 int[] 类型不符,xUnit1010 在编译期拦截(见 4.2)")]
#pragma warning disable xUnit1010
[InlineData(new object?[] { 500, 1000 }, ShippingZone.Eu, false, 55.50)]
#pragma warning restore xUnit1010
public void EstimateBatch_WrongArrayShape(
    int[] weightGrams, ShippingZone zone, bool express, decimal expected)
    => Assert.Equal(expected, estimator.EstimateBatch(weightGrams, zone, express));
```

去掉 `#pragma`,编译期就有:

```text
error xUnit1010: The value is not convertible to the method parameter 'weightGrams' of type 'int[]'. Use a compatible data value. (https://xunit.net/xunit.analyzers/rules/xUnit1010)
```

顺带一句:这行的 `Skip` 只是为了把演示留在工程里。保留 `#pragma`、去掉 `Skip`,它其实会通过——绑定参数时 xUnit 能把 `object?[]` 逐元素转成 `int[]`;真正拦住它的是编译期的类型检查。

顺带一个有用的分析器:两行数据完全相同会被指出(`xUnit1025: … has InlineData duplicate(s)`),不用担心复制粘贴留下重复覆盖。

最后一句预告:每行也有 `DisableParallelization` 命名参数(`[InlineData(500, ShippingZone.Eu, false, 24.50, DisableParallelization = true)]`),它只影响这一行的并行方式,第 6 章展开。

## 4.3 MemberData:数据源可以是方法、属性、字段

数据一旦超过十几行、需要生成、或者要跨测试类共享,就不该再写在特性里。`[MemberData(nameof(成员名))]` 指向一个**公共静态**成员;写成实例成员会被分析器拦下:

```text
error xUnit1017: MemberData must reference a static member. Add the static modifier to the data member. (https://xunit.net/xunit.analyzers/rules/xUnit1017)
```

### 三种行格式

[`MemberDataTests.cs`](../code/Ch04.Parameterized/MemberDataTests.cs) 里三种格式各一份。

格式一:`object?[]`,最直白,也最没有类型保护。数据源是属性:

```csharp
// 数据源:属性;行格式一:object?[]
public static IEnumerable<object?[]> InvalidTrackingNumbers =>
[
    new object?[] { null },
    new object?[] { "" },
    new object?[] { "SF12345678901" },
    new object?[] { "SF1234567890123" },
    new object?[] { "AB123456789012" },
    new object?[] { "SF123456789O12" },
];

[Theory]
[MemberData(nameof(InvalidTrackingNumbers))]
public void TryParse_InvalidTrackingNumber_ReturnsFalse(string? input)
    => Assert.False(TrackingNumberParser.TryParse(input, out _));
```

格式二:元组。带字段名的元组可读性好,而且类型是编译期检查的:

```csharp
// 数据源:方法;行格式二:元组(字段名会出现在参数列表里,可读性好)
public static IEnumerable<(ShippingZone Zone, int JustInside, int JustOutside, decimal StepPrice)> StepBoundaryRows() =>
[
    (ShippingZone.Domestic, 500, 501, 3.00m),
    (ShippingZone.Eu, 1_000, 1_001, 6.50m),
    (ShippingZone.International, 1_500, 1_501, 11.00m),
];

[Theory]
[MemberData(nameof(StepBoundaryRows))]
public void Estimate_CrossingWeightStep_AddsExactlyOneStepPrice(
    ShippingZone zone, int justInside, int justOutside, decimal stepPrice)
{
    var insidePrice = estimator.Estimate(justInside, zone, express: false);
    var outsidePrice = estimator.Estimate(justOutside, zone, express: false);

    Assert.Equal(stepPrice, outsidePrice - insidePrice);
}
```

格式三:`TheoryDataRow<T…>`,能携带元数据(4.6):

```csharp
// 数据源:方法;行格式三:ITheoryDataRow(可携带元数据,4.6 展开)
public static IEnumerable<TheoryDataRow<string, string, string>> KnownCarrierRows() =>
[
    new TheoryDataRow<string, string, string>("SF", "SF123456789012", "123456789012"),
    new TheoryDataRow<string, string, string>("YT", "YT000000000001", "000000000001"),
    new TheoryDataRow<string, string, string>("JD", "JD999999999999", "999999999999")
    {
        Skip = "JD 号段规则尚未冻结,先挂起",
    },
];
```

### async 数据源

数据源可以是 `Task<…>` 或 `ValueTask<…>`:读文件、查库、调接口都行。[`TestData/LegacyTrackingNumberRows.cs`](../code/Ch04.Parameterized/TestData/LegacyTrackingNumberRows.cs) 是这种数据源的落脚点——遗留系统里已经开出过的运单号,必须永远能被解析:

```csharp
public static class LegacyTrackingNumberRows
{
    private const string legacyNumbers = """
        SF000000000001
        YT100000000002
        JD200000000003
        """;

    public static async Task<IEnumerable<object?[]>> RoundTripRowsAsync()
    {
        // 真实项目里这里通常是 await File.ReadAllLinesAsync(...) 或一次数据库查询
        var lines = legacyNumbers.Split('\n', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
        var rows = lines.Select(line => new object?[] { line }).ToList();

        await Task.Yield();
        return rows;
    }
}
```

消费它要跨类型,见下一小节。

### 带参数的数据源

`[MemberData]` 的额外参数会喂给数据方法,不是喂给测试方法。同一个生成器,配上不同参数,就服务多个测试:

```csharp
// 带参数的数据源:Arguments 只喂给数据方法,测试方法想要同一个值就把它写进行里
public static IEnumerable<object?[]> PriceRowsFor(ShippingZone zone)
{
    var (firstWeightPrice, stepPrice) = ZonePriceTable(zone);

    yield return new object?[] { 500, zone, false, firstWeightPrice };
    yield return new object?[] { 1_000, zone, false, firstWeightPrice + stepPrice };
    yield return new object?[] { 500, zone, true, firstWeightPrice + ExpressSurcharge };
}

[Theory]
[MemberData(nameof(PriceRowsFor), ShippingZone.Eu)]
public void Estimate_EuZonePriceTable_ReturnsExpectedPrice(
    int weightGrams, ShippingZone zone, bool express, decimal expected)
    => Assert.Equal(expected, estimator.Estimate(weightGrams, zone, express));
```

注意 `ZonePriceTable` 是测试侧独立写一遍的规格表(12.00 / 24.50 / 55.00 这些价目),不是引用生产代码里的常量——用实现里的数验证实现,测不出任何东西。同一个生成器再配一个 `ShippingZone.International`,就得到 `Estimate_InternationalZonePriceTable_ReturnsExpectedPrice`:两个测试方法体完全一样,只有 Arguments 不同。

### 数据源在别的类型里

跨类型引用必须写 `MemberType`,否则分析器认为你在找本类的成员:

```csharp
[Theory]
[MemberData(nameof(LegacyTrackingNumberRows.RoundTripRowsAsync), MemberType = typeof(LegacyTrackingNumberRows))]
public void Parse_LegacyTrackingNumber_RoundTripsToSameString(string input)
{
    var parsed = TrackingNumberParser.Parse(input);

    Assert.Equal(input, parsed.ToString());
}
```

漏掉 `MemberType = typeof(...)` 的真实报错:

```text
error xUnit1015: MemberData must reference an existing member 'RoundTripRowsAsync' on type 'Ch04.Parameterized.Tests.MemberDataTests'. Fix the member reference, or add the missing data member. (https://xunit.net/xunit.analyzers/rules/xUnit1015)
```

## 4.4 ClassData:把输入表做成类

一份输入表要被多个测试类共用时,`ClassData` 比 `MemberData` + `MemberType` 更顺手:它就是一个实现了 `IEnumerable` 的类型,`[ClassData(typeof(X))]` 直接引用。

[`ClassDataTests.cs`](../code/Ch04.Parameterized/ClassDataTests.cs) 里的数据类,首选带类型的行:

```csharp
public sealed class InvalidTrackingNumberData : IEnumerable<TheoryDataRow<string?>>
{
    public IEnumerator<TheoryDataRow<string?>> GetEnumerator()
    {
        yield return new TheoryDataRow<string?>(null) { TestDisplayName = "空引用" };
        yield return new TheoryDataRow<string?>("") { TestDisplayName = "空字符串" };
        yield return new TheoryDataRow<string?>("   ") { TestDisplayName = "只有空白" };
        yield return new TheoryDataRow<string?>("SF12345678901") { TestDisplayName = "少一位" };
        yield return new TheoryDataRow<string?>("AB123456789012") { TestDisplayName = "未知承运商" };
    }

    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
}
```

同一份数据被两个测试类共用——一个测 `TryParse` 的返回值,一个测 `Parse` 的异常路径:

```csharp
[Theory]
[ClassData(typeof(InvalidTrackingNumberData))]
public void TryParse_InvalidTrackingNumber_ReturnsFalse(string? input)
    => Assert.False(TrackingNumberParser.TryParse(input, out _));

[Theory]
[ClassData(typeof(InvalidTrackingNumberData))]
public void Parse_InvalidTrackingNumber_ThrowsFormatExceptionNamingInput(string? input)
{
    var exception = Assert.Throws<FormatException>(() => TrackingNumberParser.Parse(input));

    Assert.Contains(input ?? string.Empty, exception.Message);
}
```

报告里每个显示名出现两次(两个测试类各一次),这正是复用的证据:

```text
空引用(input: null)
空字符串(input: "")
只有空白(input: "   ")
少一位(input: "SF12345678901")
未知承运商(input: "AB123456789012")
```

旧式写法 `IEnumerable<object[]>` 仍然支持。同文件里还有一个用它生成的表——数据从被测代码的公开承运商列表生成,新增承运商时测试不用改:

```csharp
/// <summary>旧式写法:实现 IEnumerable&lt;object[]&gt;。能用,但没有编译期类型检查(见 4.5)。</summary>
public sealed class KnownCarrierNumberRows : IEnumerable<object[]>
{
    public IEnumerator<object[]> GetEnumerator()
    {
        // 数据从被测代码的公开承运商表生成:新增承运商时,这里不用改
        foreach (var carrier in TrackingNumberParser.KnownCarriers)
            yield return new object[] { carrier, carrier + "123456789012" };
    }

    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
}
```

数据类的硬性要求(把构造函数改成私有,分析器就停下):

```text
error xUnit1007: ClassData must point at a valid class. The class <数据类名> must be public, not abstract, with an empty constructor, and implement IEnumerable<object[]>, IAsyncEnumerable<object[]>, IEnumerable<ITheoryDataRow>, or IAsyncEnumerable<ITheoryDataRow>. (https://xunit.net/xunit.analyzers/rules/xUnit1007)
```

## 4.5 TheoryData<T…>:把类型检查提前到编译期

`TheoryData<T1…T15>`(1–15 个类型参数,4.0.2 实测到 15 维可用)是带类型的行集合,可以直接当静态字段用。它最大的价值不是少写 `new object?[]`,而是**参数顺序和类型写错时,编译就停**。

[`TheoryDataTests.cs`](../code/Ch04.Parameterized/TheoryDataTests.cs):

```csharp
// 强类型字段 + 集合初始化器:类型、顺序、个数写错都编译不过
public static readonly TheoryData<int, ShippingZone, bool, decimal> EstimateRows = new()
{
    { 500, ShippingZone.Domestic, false, 12.00m },
    { 501, ShippingZone.Domestic, false, 15.00m },
    { 1_000, ShippingZone.Eu, false, 31.00m },
    { 1_000, ShippingZone.International, true, 81.00m },
};

[Theory]
[MemberData(nameof(EstimateRows))]
public void Estimate_StronglyTypedRows_ReturnsExpectedPrice(
    int weightGrams, ShippingZone zone, bool express, decimal expected)
    => Assert.Equal(expected, estimator.Estimate(weightGrams, zone, express));
```

需要边生成边加就用 `Add`(带类型的 `TheoryDataRow` 也能 `Add`):

```csharp
private static TheoryData<string, string> BuildValidNumberRows()
{
    var rows = new TheoryData<string, string>();

    foreach (var carrier in TrackingNumberParser.KnownCarriers)
        rows.Add($"{carrier}123456789012", carrier);

    return rows;
}
```

同一张表写成裸 `IEnumerable<object?[]>`,行为完全一样,只是没有任何东西盯着类型:

```csharp
// 没有类型参数的写法:编译器不再检查任何东西,顺序或类型写错要到运行时才看得见
public static IEnumerable<object?[]> EstimateRowsUntyped =>
[
    new object?[] { 500, ShippingZone.Domestic, false, 12.00m },
    new object?[] { 501, ShippingZone.Domestic, false, 15.00m },
    new object?[] { 1_000, ShippingZone.Eu, false, 31.00m },
    new object?[] { 1_000, ShippingZone.International, true, 81.00m },
];
```

### 类型写反:两种写法,两种发现时机

把行里的两个值顺序写反(行是 `(decimal, int)`,测试方法要 `(int, decimal)`),带类型的写法在编译期就有两条 error:

```text
error xUnit1039: The argument type decimal from TheoryDataTests.SwappedRows is not compatible with the type of the corresponding test method parameter weightGrams. (https://xunit.net/xunit.analyzers/rules/xUnit1039)
error xUnit1039: The argument type int from TheoryDataTests.SwappedRows is not compatible with the type of the corresponding test method parameter expected. (https://xunit.net/xunit.analyzers/rules/xUnit1039)
```

这段代码在 [`TheoryDataTests.cs`](../code/Ch04.Parameterized/TheoryDataTests.cs) 末尾用 `#pragma warning disable xUnit1039` 保留着,为的是让章工程零警告;去掉 `#pragma` 就能看到上面两条。

同一份错写进裸 `object?[]`,编译、发现、启动都正常——直到那一行真的执行。[`DataFailureDemosTests.cs`](../code/Ch04.Parameterized/DataFailureDemosTests.cs) 里带 `Skip` 保留着,去掉 `Skip` 跑:

```text
failed Ch04.Parameterized.Tests.DataFailureDemosTests.Estimate_SwappedUntypedRow_FailsOnlyAtRuntime(weightGrams: 12, expected: 500) (2ms)
  from .../Ch04.Parameterized.dll (net10.0|x64)
  Assert.Equal() Failure: Values differ
  Expected: 500
  Actual:   12.00
    at Ch04.Parameterized.Tests.DataFailureDemosTests.Estimate_SwappedUntypedRow_FailsOnlyAtRuntime(Int32 weightGrams, Decimal expected) in .../DataFailureDemosTests.cs:19
```

注意它没有报"类型不匹配":绑定参数时 `12.00m` 被**截断**成 `int 12`,`500` 被补成 `decimal 500`,于是失败看起来像断言写错了。这类失败最难查——数据没错、代码没错,只有顺序错了。

| 写法 | 顺序/类型错误何时暴露 |
| --- | --- |
| `[InlineData]` | 编译期(xUnit1010:类型不符;xUnit1009:数据少了;xUnit1011:数据多了) |
| `TheoryData<T…>` | 编译期(xUnit1039) |
| `IEnumerable<object?[]>` / `object[]` 行 | 运行时,且可能被静默转换掩盖 |

## 4.6 TheoryDataRow:给一行加元数据

数据行的属性在 `ITheoryDataRow` 上:`TestDisplayName`、`Skip`、`SkipUnless`、`SkipWhen`、`SkipType`、`Explicit`、`Timeout`、`Traits`、`Label`、`DisableParallelization`。本章只演示其中四个:`TestDisplayName`、`Skip`、`Timeout`、`Traits`;条件执行归第 7 章,并行归第 6 章。

第一个坑:**字段名是 `TestDisplayName`,不是 `DisplayName`。** 第 2 章讲的 `DisplayName` 是测试方法上的属性;在数据行上写 `DisplayName`,编译就停:

```text
error CS0117: 'TheoryDataRow<int>' does not contain a definition for 'DisplayName'
```

[`TheoryDataRowMetadataTests.cs`](../code/Ch04.Parameterized/TheoryDataRowMetadataTests.cs) 里两种写法都有。对象初始化器:

```csharp
// 写法一:对象初始化器,属性就是数据行的元数据字段
public static IEnumerable<TheoryDataRow<string, string>> CarrierSampleRows() =>
[
```

## 4.7 MatrixTheoryData:维度正交时用笛卡尔积

手写表覆盖"每个重量 × 每个区域"时,表格长度是各维的乘积,写起来重复、漏起来无声。`MatrixTheoryData<T1, T2>` 一直到 `MatrixTheoryData<T1, …, T15>`(2–15 维)接受各维的取值序列,自己展开笛卡尔积。

[`MatrixTheoryDataTests.cs`](../code/Ch04.Parameterized/MatrixTheoryDataTests.cs):

```csharp
// 两个维度:重量 × 区域 → 3 × 2 = 6 行
public static readonly MatrixTheoryData<int, ShippingZone> WeightByZone = new(
    [500, 1_000, 1_500],
    [ShippingZone.Domestic, ShippingZone.Eu]);

[Theory]
[MemberData(nameof(WeightByZone))]
public void Estimate_EveryWeightAndZone_QuoteLandsOnStepGrid(int weightGrams, ShippingZone zone)
{
    var quoted = estimator.Estimate(weightGrams, zone, express: false);
    var firstWeightPrice = FirstWeightPriceOf(zone);
    var stepPrice = StepPriceOf(zone);

    Assert.True(quoted >= firstWeightPrice, $"{zone} 区域 {weightGrams}g 报价 {quoted} 不应低于首重价 {firstWeightPrice}。");
    Assert.Equal(0m, (quoted - firstWeightPrice) % stepPrice);
}
```

三个维度也一样,加急与否作为独立一维(2 × 2 × 2 = 8 行):

```csharp
// 三个维度:重量 × 区域 × 是否加急 → 2 × 2 × 2 = 8 行
public static readonly MatrixTheoryData<int, ShippingZone, bool> WeightByZoneBySpeed = new(
    [500, 1_000],
    [ShippingZone.Eu, ShippingZone.International],
    [false, true]);
```

矩阵之外还能补"例外行":`Add` / `AddRange` 接受元组或 `TheoryDataRow`,报告里 5 行(2 行笛卡尔积 + 3 行补充):

```csharp
// 笛卡尔积之外还能补例外行:Add / AddRange 接受元组或 TheoryDataRow
public static MatrixTheoryData<int, ShippingZone> WeightByZoneWithExceptions()
{
    var matrix = new MatrixTheoryData<int, ShippingZone>([500, 1_000], [ShippingZone.Domestic]);

    matrix.Add(1_500, ShippingZone.Eu);
    matrix.AddRange([(2_000, ShippingZone.International)]);
    matrix.Add(new TheoryDataRow<int, ShippingZone>(2_500, ShippingZone.Eu) { TestDisplayName = "手工补充的超大件" });

    return matrix;
}
```

三条要点:

- 每个维度是普通的 `IEnumerable<T>`(数组、`List<T>`、集合表达式都行)。`TheoryData<T>` **不能**当维度用——它不是 `IEnumerable<T>`,编译器会拒绝。
- 行数就是各维长度的乘积:6、8、5 行在本章工程的报告里都能数出来。矩阵适合"断言本身是规则"或"只查不变量"的场景;要逐行断言精确值,就回到手写表。
- 维度必须真的正交。拿布尔开关凑维度、或者某一维对结果没有影响,就是在制造重复覆盖(4.9 有反例)。

## 4.8 显示名与过滤:定位到具体一行

默认显示名的构成是 `命名空间.类名.方法名(参数名: 值, …)`。值的打印形式由类型决定,几个常见的:

| 数据 | 显示形态 |
| --- | --- |
| `ShippingZone.Eu` | `zone: Eu` |
| `bool` | `express: False` |
| double `31.00` | `expected: 31` |
| decimal `24.50m` | `expected: 24.50` |
| `new[] { 500, 1000 }` | `weightGrams: [500, 1000]` |
| `null` | `input: null` |

`TestDisplayName` 替换的是 `命名空间.类名.方法名` 这一段,参数列表照旧(4.6 的输出就是这么来的)。

要把"某一行为什么失败"变成"只重跑这一行",需要它的显示名。最可靠的来源是报告文件:

```shell
$ dotnet test --project Ch04.Parameterized -- --report-xunit-xml
  In process file artifacts produced:
    - .../bin/Debug/net10.0/TestResults/lindesty_homearch_2026-10-23_02_12_13.119199.xunit.xml
```

XML 里每个 `<test name="…">` 就是可用于过滤的字符串(名字里的引号在 XML 里写成 `\&quot;`,填命令行时用未转义的形式)。整名精确匹配:

```shell
$ dotnet test --project Ch04.Parameterized -- --filter-display-name "Ch04.Parameterized.Tests.MatrixTheoryDataTests.Estimate_ExpressOnlyAddsFixedSurcharge(weightGrams: 500, zone: Eu, express: False)"

Test run summary: Passed!
  total: 1
  failed: 0
  succeeded: 1
  skipped: 0
```

带 `*` 的前缀/后缀/包含匹配同样有效,自定义显示名让这一步很省事:

```shell
$ dotnet test --project Ch04.Parameterized -- --filter-display-name "欧区首重*"

Test run summary: Passed!
  total: 1
  failed: 0
  succeeded: 1
  skipped: 0
```

想让默认显示名更适合人读,`xunit.runner.json` 有 `methodDisplay`(`"classAndMethod"` 或 `"method"`)与 `methodDisplayOptions`(`"replaceUnderscoreWithSpace"`、`"useOperatorMonikers"`、`"useEscapeSequences"`、`"replacePeriodWithComma"`、`"removeAsyncSuffix"`,或 `"all"` / `"none"`)。它们是全局规则;某一行的名字还是 `TestDisplayName` 说了算。

## 4.9 三个反模式

[`ParameterizedAntiPatternTests.cs`](../code/Ch04.Parameterized/ParameterizedAntiPatternTests.cs) 里存着三个能跑通但不该这样写的例子,全部通过,故意留着对照。

**把断言逻辑塞进数据。** 数据列里出现"期望的异常文案",期望就退化成字符串相等:

```csharp
public static IEnumerable<object?[]> MessageRows() =>
[
    new object?[] { "SF12345678901", "“SF12345678901” 不是合法的运单号。" },
    new object?[] { "AB123456789012", "“AB123456789012” 不是合法的运单号。" },
];
```

改文案要改数据,数据里读不出行为。要断言异常,就断言行为(消息里包含输入,见 4.4);要说清这行测什么,就用 `TestDisplayName`。

**一行数据覆盖多个行为。** 解析与报价挤在同一条测试里,失败时只知道"这行不对":

```csharp
public static IEnumerable<object?[]> MixedBehaviorRows() =>
[
    new object?[] { "SF123456789012", "SF", 500, 12.00m },
    new object?[] { "YT000000000001", "YT", 1_000, 15.00m },
];
```

两个行为各一个测试(第 2 章的判定),数据各自最小。

**用矩阵制造重复覆盖。** 承运商这一维与"数字部分非法"无关,12 行里只有 4 种分支:

```csharp
// 反例三:矩阵爆炸 —— 承运商这一维与"数字部分非法"无关,
// 3 × 4 = 12 行里只有 4 种真实分支,其余 8 行是重复覆盖。
public static readonly MatrixTheoryData<string, string> CarrierByBadDigits = new(
    ["SF", "YT", "JD"],
    ["12345678901", "1234567890123", "123456789O12", "123456789012X"]);
```

矩阵的代价是乘法的:五维每维 5 个值就是 3125 行。加维度之前先问一句——这一维真的会改变结果吗?布尔开关尤其可疑:它通常意味着两套行为,该拆测试(第 2 章)。

## 本章小结

- 数据行是独立测试:计数、失败、过滤、元数据都按行算。本章 29 个测试方法展开成 108 个测试用例。
- `[InlineData]` 只接受编译期常量:字符串、字符、数值、布尔、枚举成员、`typeof`、`const`/`nameof`、数组创建表达式;`decimal` 字面量与 `static readonly` 都会撞 CS0182,小数只能写 double 字面量。
- `new object?[] { … }` 作为唯一数据时就是 `params` 数组本身,会被摊平成多个参数(运行时报"expected 1 parameter value, but 2 parameter values were provided");要传数组就用具体元素类型(`new[] { 500, 1000 }`)。类型或个数对不上,分析器在编译期就停:xUnit1010(类型不符)、xUnit1009(数据少了)、xUnit1011(数据多了)。
- `[MemberData]` 指向公共静态成员(实例成员报 xUnit1017);跨类型要写 `MemberType`(否则 xUnit1015)。行格式三种:`object?[]`、元组、`TheoryDataRow<T…>`;数据源可以是方法、属性、字段,也可以是 `Task` / `ValueTask`。
- `[ClassData]` 的数据类必须 public、非抽象、有无参构造,实现 `IEnumerable<object[]>` / `IAsyncEnumerable<object[]>` / `IEnumerable<ITheoryDataRow>` / `IAsyncEnumerable<ITheoryDataRow>`(xUnit1007)。它适合被多个测试类共用的输入表。
- `TheoryData<T1…T15>` 把顺序与类型错误停在编译期(xUnit1039,默认 error 级别);裸 `IEnumerable<object?[]>` 的同类错误到运行时才出现,而且会被静默的类型转换(如 `12.00m` 截断成 `12`)掩盖。
- 数据行元数据字段名是 `TestDisplayName`(不是 `DisplayName`)、`Skip`、`Timeout`、`Traits`(`Dictionary<string, HashSet<string>>`)等;有 `WithSkip` / `WithTestDisplayName` / `WithTimeout` / `WithTrait` 的 fluent 写法。`Skip` 的文本就是报告里的跳过原因。
- 设了 `Timeout` 的测试要观察 `TestContext.Current.CancellationToken`;超时失败显示为 `failed (canceled) … Test execution timed out after N milliseconds`。
- `MatrixTheoryData<T1…T15>`(2–15 维)展开各维的笛卡尔积,维度是普通 `IEnumerable<T>`(`TheoryData<T>` 不行),`Add` / `AddRange` 可补例外行。只在维度真正正交时使用。
- 定位单行:`--report-xunit-xml` 里的 `name=` 就是过滤字符串,`--filter-display-name`(支持 `*`)与 `--filter-trait "k=v"` 都能精确到行;`xunit.runner.json` 的 `methodDisplay` / `methodDisplayOptions` 改变默认显示名,`TestDisplayName` 覆盖单行。
