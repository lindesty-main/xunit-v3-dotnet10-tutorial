# 第 3 章 · 断言

> 你将学会:
>
> - 读懂断言失败输出里的 `Expected` / `Actual` / 位置箭头 / 堆栈,并区分"断言失败"与"测试代码抛异常"
> - 按语义选对基础断言:`Equal` 走 `Equals` 与序列比较,`Same` 只认引用,`Equivalent` 跨类型比结构
> - 用 `StringComparison` 与四个 bool 命名参数做字符串宽松比较,用 `tolerance` / `precision` 比较浮点与时间
> - 用 `Contains` / `All` / `Single` / `Collection` / `Distinct` 等集合断言精确描述对集合的期望
> - 用 `Throws<T>` / `ThrowsAny` / `Record.Exception` 断言异常,并避开"表达式体 lambda 绑定到过时重载"这个编译坑
> - 用 `Assert.Multiple` 一次报告一个行为的多条证据,用自定义扩展方法组织重复断言

本章的工程是 [`code/Ch03.Assertions`](../code/Ch03.Assertions)。所有输出片段来自本机 .NET SDK 10.0.113 + xUnit.net v3 4.0.2 的真实运行,过长的绝对路径用 `...` 省略;runner 在每个失败下面打印的 `from <测试 dll>` 提示行、以及测试帧之后的反射调用帧已略去,其余逐字保留。

## 3.1 断言的本质与失败输出解读

一条断言就是一次"值不符预期就抛异常"的检查:通过则正常返回,测试继续;失败则抛出一个 `Xunit.Sdk.*Exception`(如 `EqualException`),测试立即终止。这就是为什么断言必须放在测试的最后一段(Act 之后):断言失败之后的代码不会执行。

看一个故意写错的断言([`AssertionFailureDemosTests.cs`](../code/Ch03.Assertions/AssertionFailureDemosTests.cs),带 `Skip`,去掉即可复现):

```csharp
[Fact]
public void Equal_string_failure() => Assert.Equal("ORD-1001", "ORD-1002");
```

真实输出:

```text
failed Ch03.Assertions.Tests.AssertionFailureDemosTests.Equal_string_failure (1ms)
  Assert.Equal() Failure: Strings differ
                    ↓ (pos 7)
  Expected: "ORD-1001"
  Actual:   "ORD-1002"
                    ↑ (pos 7)
    at Ch03.Assertions.Tests.AssertionFailureDemosTests.Equal_string_failure() in .../AssertionFailureDemosTests.cs:13
```

读法:`Assert.Equal() Failure` 说明是哪个断言失败,`Strings differ` 说明失败类别;`pos 7` 指向第一个不同的字符,上下两个箭头分别指向 Expected 与 Actual 的同一位置;最后一行是抛出点的文件与行号。

失败分两类,输出形状不同。第二类是测试代码自己抛异常——比如 Arrange/Act 里的空引用、越界:

```csharp
[Fact]
public void Raw_exception_failure()
{
    var empty = new OrderLine[0];
    _ = empty[3];
}
```

```text
failed Ch03.Assertions.Tests.AssertionFailureDemosTests.Raw_exception_failure (0ms)
  Xunit.MicrosoftTestingPlatform.XunitException: System.IndexOutOfRangeException : Index was outside the bounds of the array.
    at Ch03.Assertions.Tests.AssertionFailureDemosTests.Raw_exception_failure() in .../AssertionFailureDemosTests.cs:22
```

区分方法:消息以 `Assert.XXX() Failure` 开头的是断言失败,说明"行为与期望不符";以异常类型开头的是测试代码崩了,通常是测试自身写错或被测代码有 bug。两类都需要修,但修的对象不同。

还有一类输出值得警惕——Expected 与 Actual 打印得一模一样:

```text
failed Ch03.Assertions.Tests.AssertionFailureDemosTests.Equal_same_looking_numbers_failure (0ms)
  Assert.Equal() Failure: Values differ
  Expected: 1
  Actual:   1
```

这条断言是 `Assert.Equal<object>(1, 1.0)`:两个值打印相同,但一个是 `int` 一个是 `double`。`Equal` 不做跨 CLR 类型的数值通融(见 3.2)。看到"打印一样却失败",先怀疑类型不同。

`True`/`False` 的可选 `userMessage` 会原样成为失败消息,没有任何前缀:

```csharp
var refundApproved = false;
Assert.True(refundApproved, "退款应当已经被批准。");
```

```text
  退款应当已经被批准。
    at Ch03.Assertions.Tests.AssertionFailureDemosTests.True_with_user_message_failure() in .../AssertionFailureDemosTests.cs:29
```

`userMessage` 只有 `string` 一种,没有 `Func<string>` 惰性重载;消息无论如何都会构造,别为省字符串拼接纠结。

## 3.2 基础断言:布尔、空引用、引用同一性、值相等

这一族的实现在 [`BasicAssertionTests.cs`](../code/Ch03.Assertions/BasicAssertionTests.cs)。

`True` / `False` 检查布尔条件(`userMessage` 只在失败时打印)。分析器会拦下几类误用:`Assert.True(false, "…")` 应写成 `Assert.Fail("…")`(xUnit2020);`Assert.Equal(null, x)` / `Assert.NotEqual(null, x)` 应写成 `Assert.Null` / `NotNull`(xUnit2003);`Assert.True(list.Contains(x))` 应写成 `Assert.Contains(x, list)`(xUnit2017)。

`Fail(message)` 让测试立即失败,消息完全自己写;3.8 的 `IsShipped` 就是它的实战用法。

`Null` / `NotNull` 检查引用是否为空——不要用 `Assert.True(x is null)` 或 `Assert.Equal(null, x)` 代替,后两者的失败输出没有针对性。

`Same` / `NotSame` 只比较引用同一性(是不是同一个对象),不看内容:

```csharp
var customer = new Customer { Name = "Ada" };
Customer sameReference = customer;
var lookalike = new Customer { Name = "Ada" };

Assert.Same(customer, sameReference);
Assert.NotSame(customer, lookalike);
```

`Equal` / `NotEqual` 是本章最重要的断言,语义按参数类型分三条:

1. **值类型与 record**:`Equal(42, 42)` 按值比较;`record` 由编译器合成了按成员的 `Equals`,所以 `Assert.Equal(new OrderLine("SKU-9", 2, 10m), new OrderLine("SKU-9", 2, 10m))` 通过。
2. **普通引用类型**:走 `Equals`。`Customer` 没有重写 `Equals`,字段完全相同的两个实例也不相等:

```csharp
var failure = Record.Exception(() =>
    Assert.Equal(new Customer { Name = "Ada" }, new Customer { Name = "Ada" }));
// Customer 没有重写 Equals,Equal 退化为引用比较。
Assert.NotNull(failure); // "Values differ"
```

跨类型的结构相等交给 3.6 的 `Equivalent`,或者给类型实现 `Equals`。

3. **集合**:按序逐元素比较,不要求 CLR 集合类型相同——数组与 `List<T>` 可以互比:

```csharp
var actual = new List<string> { "SKU-1", "SKU-2" };
Assert.Equal(new[] { "SKU-1", "SKU-2" }, actual);
```

顺序不同即失败,输出会指出第一个不同的位置:

```text
failed Ch03.Assertions.Tests.AssertionFailureDemosTests.Collection_order_failure (6ms)
  Assert.Equal() Failure: Collections differ
                ↓ (pos 1)
  Expected: [1, 2, 3]
  Actual:   [1, 3, 2]
                ↑ (pos 1)
```

`Equal` 不做跨 CLR 类型的数值通融:`Assert.Equal<object>(1, 1.0)` 失败,`Assert.Equal<object>(1, 1L)` 同样失败。要跨类型比,用 `Equivalent`(3.6)。

## 3.3 字符串与数值断言

### 子串匹配:Contains / StartsWith / EndsWith

[`StringAssertionTests.cs`](../code/Ch03.Assertions/StringAssertionTests.cs)。对字符串,`Contains` / `DoesNotContain` / `StartsWith` / `EndsWith` 检查子串。不显式给比较方式时,官方 API 文档写明子串匹配按**当前区域(culture)**进行;要确定性结果就显式传 `StringComparison`:

```csharp
var message = "Order no. ORD-1001";

Assert.Contains("ord-1001", message, StringComparison.OrdinalIgnoreCase);
Assert.StartsWith("order NO", message, StringComparison.OrdinalIgnoreCase);
Assert.EndsWith("ORD-1001", message, StringComparison.OrdinalIgnoreCase);
Assert.DoesNotContain("INVOICE", message, StringComparison.OrdinalIgnoreCase);
```

### Equal(string, string):四个 bool 命名参数

字符串的 `Equal` 区分大小写(`Equal("A", "a")` 失败)。它**没有** `Equal(string, string, StringComparison)` 重载;宽松比较走四个默认 `false` 的命名参数,含义以官方 API 文档为准:

| 参数 | 语义 |
| --- | --- |
| `ignoreCase: true` | 忽略大小写差异,按不变文化(invariant culture)比较 |
| `ignoreLineEndingDifferences: true` | `\r\n`、`\r`、`\n` 视为等价 |
| `ignoreWhiteSpaceDifferences: true` | 任意**非零**数量的连续水平空白(空格、制表符等)视为等价 |
| `ignoreAllWhiteSpace: true` | 水平空白可有可无:连"零个"也视为等价 |

```csharp
Assert.Equal("ORD-ABC", "ord-abc", ignoreCase: true);
Assert.Equal("a\r\nb", "a\nb", ignoreLineEndingDifferences: true);
Assert.Equal("a  b", "a b", ignoreWhiteSpaceDifferences: true);
Assert.Equal("a b\tc", "abc", ignoreAllWhiteSpace: true);
```

想要"整串忽略大小写相等"的完整替代写法:`Equal(..., ignoreCase: true)`,或者 `Contains(expected, actual, StringComparison.OrdinalIgnoreCase)` 加上 `DoesNotContain` 反向检查。

### 浮点、decimal、时间

[`NumericAssertionTests.cs`](../code/Ch03.Assertions/NumericAssertionTests.cs)。`0.1 + 0.2` 等于 `0.30000000000000004`,裸 `Equal` 必挂。三种通融方式:

```csharp
// tolerance:允许固定的绝对偏差
Assert.Equal(0.1 + 0.2, 0.3, tolerance: 1e-9);

// precision:两边各自四舍入到 N 位小数再比较
Assert.Equal(0.1 + 0.2, 0.3, precision: 6);

// MidpointRounding 控制中点舍入方向:1.5 与 2.4 取整到 0 位都归到 2
Assert.Equal(1.5, 2.4, precision: 0, rounding: MidpointRounding.ToEven);
```

`decimal` 只有 `precision`,没有 `tolerance`:`Assert.Equal(10.123m, 10.124m, precision: 2)`。`DateTime` / `DateTimeOffset` 用 `TimeSpan precision` 表示允许的时间窗——断言"下单时间在采样时刻之后 30 秒内":

```csharp
var before = DateTimeOffset.UtcNow;
var order = new OrderService().Create("cust-1", lines);
Assert.Equal(before, order.PlacedAt, precision: TimeSpan.FromSeconds(30));
```

## 3.4 集合断言

[`CollectionAssertionTests.cs`](../code/Ch03.Assertions/CollectionAssertionTests.cs)。被测对象是 `OrderService.Create` 返回的订单,两条明细:`SKU-1 x2 @10`、`SKU-2 x1 @5`。

### Contains / DoesNotContain

这里用到三种形态:元素(按 `Equals`)、谓词、字典键(字符串、`Span`/`Memory` 另有各自的重载)。字典形态**返回命中的值**,可以直接续断言:

```csharp
Assert.Contains(lines[0], order.Lines);
Assert.Contains(order.Lines, line => line.Quantity > 1);

var prices = new Dictionary<string, decimal> { ["SKU-1"] = 10m };
var price = Assert.Contains("SKU-1", prices);
Assert.Equal(10m, price);
Assert.DoesNotContain("SKU-9", prices);
```

v3 **没有 `Assert.Any`**(官方 API 里不存在,调用会报 CS1501)。"存在满足条件的元素"就是 `Contains` 的谓词重载;失败输出是 `Filter not matched in collection`。

### All:逐元素检查

```csharp
Assert.All(order.Lines, line => Assert.True(line.Quantity > 0));
```

坑:空集合的 `All` **默认直接通过**。要表达"非空且全部满足",显式传 `throwIfEmpty: true`——4.0.2 的参数名是 `throwIfEmpty`(4.0.0 发布说明里叫 `strict`,实现最终改名了):

```csharp
Assert.All(Array.Empty<OrderLine>(), line => Assert.True(line.Quantity > 0)); // 空集合:通过
var empty = Record.Exception(() =>
    Assert.All(Array.Empty<OrderLine>(), line => Assert.True(line.Quantity > 0), throwIfEmpty: true));
Assert.NotNull(empty); // 要求非空:失败
```

### Single:有且只有一个

```csharp
var expensive = Assert.Single(order.Lines, line => line.UnitPrice > 9m);
Assert.Equal("SKU-1", expensive.Sku);
```

零个或多个匹配都失败,并把集合打印出来。`Single` 返回元素,方便续断言——第 2 章 2.2 的 `var violation = Assert.Single(violations);` 用的就是它。

### Collection / CollectionAsync:逐元素配检查器

`Collection` 要求元素数量与检查器数量一致,按序一对一执行:

```csharp
Assert.Collection(order.Lines,
    line => Assert.Equal("SKU-1", line.Sku),
    line => Assert.Equal("SKU-2", line.Sku));
```

检查器少一个都失败(`Mismatched item count`)。它比 `All` 强的地方是每个元素可以有**不同**的期望;异步检查器用 `CollectionAsync`(`await`)。

### Distinct / Empty / NotEmpty

```csharp
Assert.Distinct(lines.Select(line => line.Sku));
Assert.NotEmpty(order.Lines);
Assert.Empty(new List<OrderLine>());
```

分析器 xUnit2029:"集合里不存在满足条件的元素"应该写 `Assert.DoesNotContain(order.Lines, line => line.Quantity > 99)`,而不是 `Assert.Empty(filtered)`——前者的失败输出带整个集合的内容,可诊断性强得多。`Empty` 只用于真正要断言为空的集合。

### Equal + 自定义比较器

`Equal` / `NotEqual` / `Contains` 都接受 `IEqualityComparer<T>` 或 `(x, y) => bool` 形式的比较器:

```csharp
Assert.Equal(new[] { 1, 2 }, new[] { 11, 22 }, (x, y) => y == x * 11);
Assert.Contains(3, new[] { 1, 2, 40 }, new RangeComparer()); // |x-y| <= 20 即视为相等
```

## 3.5 异常断言

[`ExceptionAssertionTests.cs`](../code/Ch03.Assertions/ExceptionAssertionTests.cs)。被测行为:`OrderService.Create(null, …)` 抛 `ArgumentNullException(ParamName="customerId")`;重复 `Ship` 抛 `InvalidOperationException`;空明细抛 `ArgumentOutOfRangeException(ParamName="lines")`。

### Throws 与 ThrowsAny

`Throws<T>` 要求**精确类型**,派生类型不算命中,并返回异常实例供继续断言:

```csharp
var ex = Assert.Throws<ArgumentNullException>(() => service.Create(null!, oneLine));
Assert.Equal("customerId", ex.ParamName);
```

按基类接会失败(`Exception type was not an exact match`);要"该类型及其派生类"就用 `ThrowsAny<T>`:

```csharp
var ex = Assert.ThrowsAny<ArgumentException>(() => service.Create(null!, oneLine));
```

异步代码用 `ThrowsAsync<T>`,并且**必须 `await`**——不 await 拿到的是 `Task`,异常根本没被观察:

```csharp
var ex = await Assert.ThrowsAsync<InvalidOperationException>(async () =>
{
    await Task.Yield();
    throw new InvalidOperationException("网络中断,发货失败。");
});
Assert.Equal("网络中断,发货失败。", ex.Message);
```

代码没抛异常时,失败输出是:

```text
failed Ch03.Assertions.Tests.AssertionFailureDemosTests.Throws_no_exception_failure (8ms)
  Assert.Throws() Failure: No exception was thrown
  Expected: typeof(System.InvalidOperationException)
```

### paramName 重载:一步校验参数名

`Throws<T>(paramName, …)` 要求 `T` 派生自 `ArgumentException`,并校验异常的 `ParamName`:

```csharp
var ex = Assert.Throws<ArgumentOutOfRangeException>("lines",
    () => service.Create("cust-1", Array.Empty<OrderLine>()));
```

参数名不符时失败消息是 `Incorrect parameter name`。注意 `ArgumentOutOfRangeException(paramName, message)` 的 `Message` 会自动追加 ` (Parameter 'lines')`。

### inspector 重载

inspector 是 `Func<T, string?>`:返回 `null` 表示检查通过,返回字符串就是失败原因:

```csharp
var ex = Assert.Throws<InvalidOperationException>(
    () => service.Ship(ShippedOrder(), "TR-2"),
    e => e.Message.Contains("不能发货") ? null : "异常消息应包含「不能发货」");
```

也可以不用 inspector,直接对返回的实例续断言——两者等价,inspector 胜在一步到位,续断言胜在可读。

### 两个绑定坑

求值属性时抛异常,绑定到 `Throws<T>(Func<object?>)` 重载,写法就是普通的属性 lambda:

```csharp
var ex = Assert.Throws<InvalidOperationException>(() => order.TrackingNumber);
```

而在测试里**直接 throw** 的 lambda(无论表达式体还是只含 throw 的块体)会绑定到已过时的 `Throws<T>(Func<Task>)`,编译报 CS0619("You must call Assert.ThrowsAsync<T>…")。正确写法是先把代码存进 `Action` 变量:

```csharp
Action throwBoom = () => throw new InvalidOperationException("boom");
var ex = Assert.Throws<InvalidOperationException>(throwBoom);
```

### Record:只关心抛没抛

不关心异常类型和内容时,用 `Record.Exception`——它返回异常或 `null`,不做任何断言:

```csharp
var again = Record.Exception(() => service.Ship(order, "TR-2"));
Assert.NotNull(again); // 只要"确实抛了"

Assert.Null(Record.Exception(() => service.Total(order))); // 反向:断言不抛
```

异步用 `await Record.ExceptionAsync(…)`。同样注意:直接 throw 的 lambda 会撞上 `Record.Exception(Func<Task>)` 的过时重载,用 `Action` 变量或在 lambda 里调用一个方法。

## 3.6 组合与结构断言

[`StructuralAssertionTests.cs`](../code/Ch03.Assertions/StructuralAssertionTests.cs)。

### Multiple:一个行为的多条证据

普通断言序列在第一条失败处终止;`Assert.Multiple(params Action[])` 把所有检查跑完,把全部失败打包成一条断言失败。`MultipleAsync(params Func<Task>[])` 是异步版。

尺度沿用第 2 章的结论:**只用于同一个行为的多条证据**。"发货成功后状态与凭证都正确"是一个行为,三条断言是它的证据:

```csharp
Assert.Multiple(
    () => Assert.Equal("Shipped", order.Status),
    () => Assert.Equal("TR-42", order.TrackingNumber),
    () => Assert.Contains("合计 5.00", service.ReceiptFor(order)));
```

两条写错的断言一次看全([`AssertionFailureDemosTests.cs`](../code/Ch03.Assertions/AssertionFailureDemosTests.cs) 的演示,去掉 `Skip` 复现):

  Actual:   "Created"

  String:    "订单 ORD-1ad798be\nSKU-1 x1 小计 5.00\n合计 5.00\n"
  Not found: "优惠"

### Equivalent:跨类型的结构比较

`Equivalent` 不看类型,只比较公开属性/字段的值,支持嵌套结构。`Product`(领域类型)与 `ProductDto`(DTO)是两个不相关的类,成员一致即等价:

```csharp
Assert.Equivalent(product, dto);
Assert.Equivalent(1, 1.0); // 数值按值比较,不看 CLR 类型——这一点 Equal 不做
```

非严格模式(默认)允许 `actual` 比 `expected` **多出**成员或数据——"期望里写的都必须对,额外不管":

```csharp
// actual 多成员:通过
Assert.Equivalent(new { Name = "机械键盘" },
    new ProductDto { Name = "机械键盘", Price = 399m, UpdatedAt = DateTimeOffset.UnixEpoch });
// actual 缺成员:失败,"Mismatched member list"
// 集合同理:expected 是 actual 的子集即可通过
Assert.Equivalent(new[] { 1 }, new[] { 1, 2 });
```

`strict: true` 收紧为"成员列表 / 集合数据必须精确一致,多出来的也不行"。

### EquivalentWithExclusions:排除指定成员

时间戳这类必然不同的成员,用表达式排除——编译期检查成员存在,重构安全;字符串形式适合匿名类型等写不出表达式的场合:

```csharp
Assert.EquivalentWithExclusions(stored, dto, p => p.UpdatedAt);
Assert.EquivalentWithExclusions(stored, dto, "UpdatedAt");
```

### StrictEqual / NotStrictEqual:不通融的 Equal

`StrictEqual` 用类型的默认比较器做严格比较,不做 `Equal` 对集合的那类跨 CLR 类型通融:

```csharp
Assert.Equal<IEnumerable<int>>(new[] { 1 }, new List<int> { 1 }); // Equal:通过(序列比较)
var failure = Record.Exception(() =>
    Assert.StrictEqual<IEnumerable<int>>(new[] { 1 }, new List<int> { 1 })); // StrictEqual:失败
Assert.NotNull(failure);
```

同类型同值的 record 两者都通过。需要"值相等且类型也严格"时用 `StrictEqual`;需要"跨类型结构相等"时用 `Equivalent`。

## 3.7 事件断言简介

[`EventAssertionTests.cs`](../code/Ch03.Assertions/EventAssertionTests.cs)。`RaisesAny<T>` 接三个参数:挂接事件、摘除事件、触发事件的代码;返回值携带 `Sender` 与事件参数(属性名是 `Arguments`):

```csharp
var raised = Assert.RaisesAny<OrderShippedEventArgs>(
    handler => service.Shipped += handler,
    handler => service.Shipped -= handler,
    () => service.Ship(order, "TR-42"));

Assert.Same(service, raised.Sender);
Assert.Equal("TR-42", raised.Arguments.TrackingNumber);
```

反向断言用 `NotRaisedAny<T>`:代码执行完没有触发事件就通过,例如确认"只算金额不会触发发货事件":

```csharp
Assert.NotRaisedAny<OrderShippedEventArgs>(
    handler => service.Shipped += handler,
    handler => service.Shipped -= handler,
    () => service.Total(order));
```

挂接/摘除这两个参数按事件委托的签名分重载:本章用的 `EventHandler<T>`,以及 `Action<T>`,都走带类型参数的 `RaisesAny<T>` / `NotRaisedAny<T>`;不带事件参数的裸 `EventHandler` 有对应的不带类型参数重载。`RaisesAnyAsync` / `NotRaisedAnyAsync` 对应异步触发代码。

## 3.8 自定义断言与控制失败输出

### 扩展方法包装

重复出现的断言组合包成扩展方法,**返回被验证的值**以支持链式([`AssertExtensions.cs`](../code/Ch03.Assertions/AssertExtensions.cs)):

```csharp
public static OrderLine HasTotal(this OrderLine line, decimal expectedTotal)
{
    Assert.Equal(expectedTotal, line.LineTotal);
    return line;
}

public static Order IsShipped(this Order order)
{
    if (order.Status != "Shipped")
        Assert.Fail($"期望订单 {order.Id} 处于 Shipped 状态,实际状态是 {order.Status}。");
    return order;
}
```

用法:`line.HasTotal(20m).HasQuantityAtLeast(1);`。失败消息用 `Assert.Fail` 写成一句人话,包含定位问题所需的具体值——这比 `Assert.True(order.Status == "Shipped", "应已发货")` 的信息量大得多。

### OverrideMax*:控制失败输出的详略

断言失败消息打印集合、对象、字符串时有默认上限。四个 `Assert.OverrideMax*` 方法只影响**当前测试**内的输出(4.0 新增):

- `OverrideMaxEnumerableLength(int?)` — 集合打印的元素个数
- `OverrideMaxObjectDepth(int?)` — 复杂对象递归深度
- `OverrideMaxObjectMemberCount(int?)` — 对象打印的成员个数
- `OverrideMaxStringLength(int?)` — 字符串打印长度,超出截断

```csharp
Assert.OverrideMaxStringLength(10);
Assert.Equal(new string('a', 100), new string('b', 100));
```

失败输出里两边各只打印 10 个字符加省略号(`"aaaaaaaaaa"···`),而不是整段百字长串:

```text
  Assert.Equal() Failure: Strings differ
             ↓ (pos 0)
  Expected: "aaaaaaaaaa"···
  Actual:   "bbbbbbbbbb"···
             ↑ (pos 0)
```

默认值偏保守;断言失败输出看不出问题所在时(比如差异在长字符串中段),临时调大对应上限,比在测试里手动截一半再比更诚实。

## 3.9 断言选择速查表

| 要验证的事 | 用什么 |
| --- | --- |
| 布尔标志为真 / 假 | `Assert.True` / `Assert.False`(可带 userMessage) |
| 让测试立即失败,消息自己写 | `Assert.Fail` |
| 引用为空 / 不为空 | `Assert.Null` / `Assert.NotNull` |
| 是不是同一个对象实例 | `Assert.Same` / `Assert.NotSame` |
| 同类型的值相等 | `Assert.Equal` / `Assert.NotEqual` |
| 跨 CLR 类型的结构相等 | `Assert.Equivalent` |
| 严格值比较,不做类型通融 | `Assert.StrictEqual` / `Assert.NotStrictEqual` |
| 字符串包含 / 前缀 / 后缀 | `Assert.Contains` / `DoesNotContain` / `StartsWith` / `EndsWith`(+`StringComparison`) |
| 字符串忽略大小写 / 行尾 / 空白 | `Assert.Equal(…, ignoreCase / ignoreLineEndingDifferences / ignoreWhiteSpaceDifferences / ignoreAllWhiteSpace: true)` |
| 浮点允许偏差 / 各自舍入到 N 位 | `Assert.Equal(…, tolerance: …)` / `Assert.Equal(…, precision: N[, rounding])` |
| 时间相差在窗口内 | `Assert.Equal(…, precision: TimeSpan)` |
| 集合含某元素 | `Assert.Contains(element, collection)` |
| 集合含满足谓词的元素 | `Assert.Contains(collection, predicate)`(v3 无 `Assert.Any`) |
| 字典含某键,并取它的值 | `var v = Assert.Contains(key, dictionary)` |
| 全部元素满足某检查 | `Assert.All`;要求非空加 `throwIfEmpty: true` |
| 有且只有一个(满足谓词) | `Assert.Single` |
| 按序逐元素各配一个检查器 | `Assert.Collection` / `CollectionAsync` |
| 无重复元素 | `Assert.Distinct` |
| 空 / 非空集合 | `Assert.Empty` / `Assert.NotEmpty`("不含满足条件的元素"用 `DoesNotContain`) |
| 精确异常类型 | `Assert.Throws<T>` / `ThrowsAsync<T>`(必须 await) |
| 异常类型及其派生类 | `Assert.ThrowsAny<T>` / `ThrowsAnyAsync<T>` |
| ArgumentException 的 ParamName | `Assert.Throws<T>("paramName", …)` |
| 异常内容细节 | inspector(`Func<T, string?>`)或对返回实例续断言 |
| 只关心抛没抛 / 不抛 | `Record.Exception` / `Record.ExceptionAsync` |
| 一个行为的多条证据 | `Assert.Multiple` / `MultipleAsync` |
| 结构比较排除个别成员 | `Assert.EquivalentWithExclusions` |
| 事件触发 / 未触发 | `Assert.RaisesAny` / `NotRaisedAny` |

## 本章小结

- 断言失败抛 `Xunit.Sdk.*Exception`;消息以 `Assert.XXX() Failure` 开头,带 Expected/Actual 与差异位置;以异常类型开头的失败是测试代码自己崩了。
- `Equal` 的语义分三条:值类型/record 按值,普通引用类型走 `Equals`,集合按序逐元素比较;它不做跨 CLR 类型的数值通融,`Equal<object>(1, 1.0)` 会失败且输出里两边打印一模一样。
- 字符串宽松比较靠 `Equal` 的四个 bool 命名参数或 `Contains`/`StartsWith`/`EndsWith` + `StringComparison`;没有 `Equal(string, string, StringComparison)` 重载。
- 数值用 `tolerance`(绝对偏差)或 `precision`(舍入到 N 位);时间用 `TimeSpan precision`。
- `All` 对空集合默认放行,要"非空且全部满足"加 `throwIfEmpty: true`;v3 没有 `Assert.Any`,谓词版 `Contains` 就是它。
- `Throws<T>` 精确类型、`ThrowsAny` 含派生;`ThrowsAsync` 必须 await;直接 throw 的 lambda 会绑定到过时重载(CS0619),用 `Action` 变量;只关心抛没抛用 `Record.Exception`。
- `Multiple` 只用于同一个行为的多条证据;`Equivalent` 跨类型比结构且非严格模式容忍 actual 多出的成员/数据;`StrictEqual` 反过来,类型严格。
- 自定义断言用扩展方法包装并返回被验证值;失败输出太简略或太冗长时用 `Assert.OverrideMax*` 在当前测试内调整。
